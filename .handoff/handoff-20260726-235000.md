### 训练命令流程

**步骤 1 — 启动容器（交互式 shell 进入）**:

```bash
MSYS_NO_PATHCONV=1 docker run --rm --gpus=all \
  -v /mnt/d:/d -v /mnt/e:/e -v /mnt/f:/f \
  -v /mnt/g:/g -v /mnt/h:/h -v /mnt/s:/s \
  -it dfl-tf2:latest /bin/bash
```

注意：**必须**使用 `MSYS_NO_PATHCONV=1` 否则 Git Bash 会把 `/mnt/d` 转译成 `D:\` 导致容器启动失败。

**步骤 2 — 在容器内执行训练**:

```bash

  --model SAEHD \

  --training-data-dst-dir /s/v_source/chenxiang/02/data_dst/aligned \
  --model-dir /h/models2/model-杨紫
```

如果不需要预览窗口，加 `--no-preview`。

## 当前阻塞问题：WSL2 盘挂载异常

### 现象
`/mnt/` 下的目录名变成了 `s;S`、`h;H` 而不是标准的 `s`、`h`：

```bash
$ ls /mnt/
d;D  e;E  f;F  g;G  h;H  s;S
```

导致 Docker 的 `-v /mnt/s:/s` 挂载绑定到空目录 —— 容器内 `/s/` 和 `/h/` 路径存在但无内容，训练报 `ValueError: No training data provided`。

### 排查方向
- Docker Desktop 设置中的 WSL2 集成配置里，确认 S/H 盘是否勾选了
- 检查 Docker Desktop → Settings → Resources → File Sharing，S 和 H 盘是否已添加
- 实际上 Docker Desktop WSL2 backend 的 `/mnt/` 应该直接映射 Windows 盘符，不需要手动挂载。`/mnt/s;S` 这种命名异常说明 WSL2 的 drvfs/9p 文件系统映射可能出了 bug
- 可能需要在 Docker Desktop 中重启 WSL2 后端

### 已验证通过的挂载
容器 inspect 显示挂载 `Source=/mnt/s → Destination=/s` 已被 Docker 接受，但 `/mnt/s` 源目录本身不正常。

验证命令：
```bash
# 在 Git Bash 中，检查 WSL2 后端挂载
docker run --rm --entrypoint ls dfl-tf2:latest -la /mnt/
# 检查 Docker Desktop 是否认到了 S 盘
docker run --rm -v /mnt/s:/tests dfl-tf2:latest ls /tests/
```

## 其他已发现的问题（优先级低）

1. **GTX Blackwell 12.0a JIT 编译**: TF 2.21 未预编译 sm_120a 的 CUDA kernel，首次训练启动会有几分钟的 PTX JIT 编译等待，后续有缓存则加快。
2. **run_dfl.sh 在 cmd 中无法使用 `./` 执行**: Windows 用户需在 Git Bash 中执行，或 cmd 中 `bash run_dfl.sh ...`。脚本里用的是 `set -e` + `docker run`，无兼容性问题。
3. **DISPLAY 设置**: 预览窗口需要 PowerShell 中 `$env:DISPLAY = "172.20.48.1:0"` + VcXsrv 运行。当前测试建议先用 `--no-preview` 确保训练能跑通。
