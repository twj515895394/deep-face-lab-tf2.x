## 1. 对话与设计要点总结

在本次会话中，我们全面解决并验证了 `deep-face-lab-tf2.x` 后端在 Windows / 跨平台环境下由于中文或 Non-ASCII 路径（`src-dir`, `dst-dir`, `model-dir` 等）引发的崩溃、乱码或读写报错问题：

1. **架构规范与 AGENTS 准则沉淀**：
   - 在项目根目录创建并确立了 [AGENTS.md](file:///t:/deep-face-lab-tf2.x/AGENTS.md) 研发规范。
   - 规定全项目所有功能（CLI 参数、模型名称、`options_json` 配置、路径输入等）必须 100% 原生支持中文与 Unicode 字符。
   - 规定图像 I/O 统一使用 `cv2ex.cv2_imread` / `cv2ex.cv2_imwrite`，文本/配置读写统一使用 `encoding='utf-8'`，Windows 平台控制台强制包装 UTF-8 标准输出流。

2. **核心代码重构与漏洞排查 (Issue 15)**：
   - **`main.py`**: 在 Windows 入口处包装 `sys.stdout` 和 `sys.stderr` 为 UTF-8 文本流，防日志打印中文路径时触发 `UnicodeEncodeError`。
   - **`core/interact/interact.py`**: 替换 `InteractDesktop.on_show_image` 在 Headless Mode 保存预览图遗留的原生 `cv2.imwrite` 为 `cv2ex.cv2_imwrite`，解除 Windows OpenCV C++ ANSI 代码页路径限制。
   - **`models/ModelBase.py`**: `save()` 写入 `summary.txt` 时补齐 `encoding='utf-8'`。
   - **`mainscripts/dev_misc.py` & `mainscripts/VideoEd.py`**: 修复文本读写 `encoding='utf-8'` 及 `video_from_sequence` 中输出父目录创建后的逻辑中断。

3. **产物沉淀与全量自动化测试**：
   - 已沉淀 Issue 规格文件：[15-chinese-path-unicode-compatibility.md](file:///t:/deep-face-lab-tf2.x/.scratch/batch1-correctness-foundation/issues/15-chinese-path-unicode-compatibility.md)。
   - 已沉淀总结报告：[15-chinese-path-unicode-compatibility-summary.md](file:///t:/deep-face-lab-tf2.x/.scratch/batch1-correctness-foundation/reports/15-chinese-path-unicode-compatibility-summary.md)。
   - 新增自动化测试：[test_chinese_path_compatibility.py](file:///t:/deep-face-lab-tf2.x/tests/smoke/test_chinese_path_compatibility.py) 与 [test_all_features_chinese_path.py](file:///t:/deep-face-lab-tf2.x/tests/smoke/test_all_features_chinese_path.py)。

## 2. 下一步待整改需求

### 需求 A：训练预览界面列数可配置化

**现状**: 当前 `onGetPreview` 方法中硬编码了一个 `resolution <= 256` 的分支判断：
- **≤256 分辨率**: 每行显示 5 列（S, SS, D, DD, SD），生成 2 个预览面板（`SAEHD` + `SAEHD masked`）
- **>256 分辨率**: 每行只显示 2 列（拆分为 6 个预览面板：`src-src`, `dst-dst`, `pred`, `masked src-src`, `masked dst-dst`, `masked pred`）

**用户期望**: 希望能灵活设置预览列数，最好能实时切换（不依赖训练参数重启），比如通过传参或运行时热键控制。
